# CQC 跨项目科学失败教训库

本库回答的不是“某一轮跑没跑过”，而是：一个项目研究了什么科学问题，实际用了什么方法，哪个主张被什么证据否定或限制，以及以后怎样避免重复犯错。详细代码、数据和实验记录仍以来源仓库为准。

## 每个任务开始时怎么读

1. 确认当前 GitHub 仓库的精确名称。
2. 打开公开仓库当前 `main` 中的 `lesson/<仓库名>.lessons.md`。网页端使用 `https://github.com/ziyu24/cqc_research_lessons/blob/main/lesson/<仓库名>.lessons.md`；程序或模型直接读取使用 `https://raw.githubusercontent.com/ziyu24/cqc_research_lessons/main/lesson/<仓库名>.lessons.md`。
3. 文件存在时先完整阅读，再接受聊天交接、历史摘要或旧稿中的科学结论；接手已有任务时尤其如此。
4. 跨项目任务只读实际涉及的文件。文件不存在时查 `INDEX.md`；没有同名文件表示“尚无已登记教训”，不表示项目正确或没有失败。
5. 本库与来源项目冲突时，回到文件列出的提交和相对证据路径复核，同时检查来源主线及更新的次线；以证据修正文档，不把本库、聊天记忆或模型版本当权威。

## 教训怎样影响新研究

教训是有边界、可修订的证据摘要，不是跨项目否决清单。引用它停止新方案前，先确认研究对象、信息条件、方法实现、评价量和适用假设确实相同；不同处不能靠项目名或方法名相似补齐。

- 一个合法反例可否定对应的普适/严格命题；有限数据上的负结果只能约束被测试的条件。项目止损、未过实用门、低功效或不显著，都不等于证明真实效应为零。
- 先确认实际执行的代码和指标定义，再解释表格：分母、比较对象、校准集合、训练/划分 seed、选择过程及基线身份必须一致。复算一致只证明可重复，不自动证明定义正确。
- 保留同时成立的正结果、负结果与未知；诊断性 GT/oracle 不能冒充可部署方法，贪心搜索不能冒充全局上界，首个已观测错误不能冒充已识别根因。
- 新颖性判断须落实到原始论文的具体命题和假设；项目内审稿评价或期刊档次自评不是同行认可，也不是科学真伪判据。修正只针对新增证据或明确错误，不为统一措辞而重写正确条目。

## 文件与条目

- 所有项目教训集中在单层 `lesson/`；一个有实质科研证据的仓库对应一个文件：`lesson/<GitHub仓库名>.lessons.md`。
- `lesson/README.md` 是该目录的短入口，`INDEX.md` 覆盖全部已审计仓库。
- 文件先写“项目研究什么”和“实际采用过的方法”，再写若干中等粒度教训。
- 每条教训固定写：失败命题、失败原因、后续做法、边界、证据。
- 内部任务号、运行器状态、文件缺失和数值调试过程不是可迁移的科学概念，不进入标题，也不单独充当教训。
- `INDEX.md` 覆盖本次审计的全部 GitHub 仓库，并区分实质科研、占位、基础设施、非论文和上游仓库。

## 项目如何新增或修订总结

1. 先在来源项目提交并推送研究问题、实际方法、结果和主要失败证据；未提交聊天结论不能作为来源。
2. 拉取本库当前 `main`，完整阅读本库 `AGENTS.md`、`README.md`、`INDEX.md` 及已有的 `lesson/<仓库名>.lessons.md`。
3. 抓取来源仓库全部远端分支。以 `main`/`master` 为主要分支；若次要分支提交更新更晚，必须同时阅读并比较，不能只看默认分支指针。
4. 只创建或修改一个 `lesson/<精确仓库名>.lessons.md`。依次写快速阅读路径、项目研究什么、领域位置与当前结论、实际采用过的方法、中等粒度教训和文末方法族停止索引。
5. 每条教训写失败命题、失败原因、后续做法、边界和证据；证据必须给出来源仓库、40 位提交号及相对路径。关键裁决须回查实际方法、代码或结果，不能只摘失败日志；依照上述使用边界区分反例、经验负结果、止损和未知。无需新增流程状态或审批。
6. 同步更新 `INDEX.md` 的审计提交、状态和教训数，运行下方两条校验命令；提交并推送后，从远端 `main` 回读提交和文档才算完成。

## 写入边界

新增或修订前必须逐库检查来源仓库，证据至少包含仓库名、40 位提交号和相对路径。不得记录密码、令牌、私钥、主机连接信息、绝对路径、完整日志、数据集、checkpoint 或未公开稿件。公开的是经过提炼的失败教训，不是私有来源仓库中的原始材料。

快速校验：

```text
python tools/validate.py .
python -m unittest -v tests.test_validate
```
